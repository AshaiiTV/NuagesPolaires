# Publication de la v296 — 23 septembre 2026

Cette livraison réunit les corrections de sécurité et de persistance de la reprise, les actions joueur dédiées et l'identité graphique Mystique polaire. Le paysage d'accueil respecte la précision de lore : les constructions anciennes ont presque toutes disparu.

## Préparation vérifiée

- La production était en v295 (`f1c5e99`), sur le site Netlify `nuages-polaires`, relié à `main` avec builds activés.
- La branche de reprise contient la totalité de `main` ; sa publication peut se faire sans réécrire l'historique.
- Les 110 tests automatisés et les trois parcours Chromium ont passé ; 46 fichiers passent le contrôle de syntaxe. Le build statique contient uniquement `index.html` et `assets/`.
- Les fonctions doivent être publiées avec le front ; `netlify.toml` cible Node 24, `npm run build`, `dist/` et `netlify/functions/`.
- `NP_SITE_URL=https://nuages-polaires.netlify.app` est défini dans le contexte production, scope Functions. Les secrets de session et la connexion existante sont conservés.
- La lecture des comptes ne révèle aucune réinitialisation obligatoire expirée ; un administrateur actif dispose d'un mot de passe normal.

## Limites et suivi

La recette distante sur une branche Neon isolée proposée dans le rapport du 21 septembre n'a pas été réalisée. La concurrence applicative est couverte par les tests SQL locaux ; la concurrence réseau réelle reste à éprouver sur un environnement dédié. Aucun test d'écriture automatisé ne doit viser la production.

Les anciennes variables de base et de session restent partagées entre contextes Netlify : préparer une base et des secrets distincts avant de tester une preview. La sauvegarde vérifiée couvre la table applicative, pas les rôles et objets PostgreSQL ni la rétention native Neon.

Les onglets v295 déjà ouverts doivent être rechargés après publication : leurs écritures sans version sont désormais refusées pour prévenir l'écrasement de données concurrentes.
