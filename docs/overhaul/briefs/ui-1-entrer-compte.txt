À CONSTRUIRE
1. /entrer : page de carnet sobre (Enveloppe visiteur ; <Page repere="NP / 00 — Entrer" titre="Rouvrir" titreVoix="le carnet."> ou formulation équivalente dans la voix). Formulaire method POST action ?/entrer : champs name="pseudo" (libellé « Pseudo ») et name="password" (libellé « Mot de passe », bouton afficher/masquer accessible), bouton « Entrer » (ruban). Erreurs : 401 « Identifiant ou mot de passe incorrect », 429 « Trop de tentatives. Réessaie dans 15 minutes. ». Lien « Pas encore de compte ? Rejoindre l'aventure → » vers /entrer/inscription. Si isDiscordEnabled() : « Entrer avec Discord » (action ?/discord), sinon rien. Compte déjà connecté : redirection vers /carnet (ou /table pour un MJ sans personnage, /atelier/bestiaire pour un designer sans personnage, /registre pour un administrateur sans personnage). Après connexion : même règle de destination ; session reset → /entrer/nouveau-mot-de-passe.
2. /entrer/inscription : l'inscription passe toujours par le règlement. Étape 1 : le règlement (getContent('reglement'), rendu comme les pages de lecture de L'univers : réutilise src/routes/univers/Lecture.svelte en l'important si son API le permet, sinon un rendu local cohérent) avec en bas « J'accepte — Continuer » ; étape 2 (?etape=compte, accessible seulement après acceptation — case cachée acceptRules transmise à l'action) : pseudo (2 à 32 caractères, règle affichée), mot de passe (8 caractères minimum), confirmation ; action ?/inscrire ; erreurs « Ce pseudo est déjà pris. », etc. Après inscription : /carnet, qui montre l'état « en attente de liaison ».
3. /entrer/nouveau-mot-de-passe : session de réinitialisation uniquement ; nouveau mot de passe + confirmation ; action ?/terminer ; explique en une phrase ce qui se passe (le code temporaire ne servira plus).
4. /compte : <Page repere="NP / 07 — Mon compte" …> chapitres : Identité (pseudo, rôle, personnage relié ou « en attente de liaison » avec la phrase 18), Mot de passe (actuel, nouveau, confirmation ; action ?/motDePasse ; note : « Les autres appareils seront déconnectés. »), Discord (si activé : lier / état), Quitter le carnet (action ?/quitter → /), Fermer le compte sous un filet double (mot de passe exigé ; phrase 20 « Le carnet se ferme pour de bon. Ce qui est écrit ne se rouvre pas. » ; refusé pour un administrateur avec le message du serveur).
5. /compte/collection : « Ma collection » : galerie de feuillets de thèmes (un feuillet = aperçu des huit tokens du thème dessiné comme une petite page : bureau, page, réglure, deux lignes d'encre, un trait de ruban), états possédé · actif · indisponible (non rendu si non visible), sélection au clavier (radiogroup), action ?/theme ; le thème s'applique immédiatement après la réponse du serveur (data-theme et data-ton sur <html>). Pas de prix, pas de « débloquer ».
6. /plus (téléphone) : la suite de la navigation en lignes de carnet : Mon journal, Mon compte, Ma collection, puis les cahiers du rôle non présents dans la bande basse, puis Quitter le carnet.
7. src/routes/+error.svelte : page d'erreur dans la voix du carnet (404 : « Cette page n'existe pas dans le carnet. » ; 401 : phrase 20 ; autres : « Le carnet n'a pas pu ouvrir cette page. » + lien retour), avec Enveloppe.
8. Accueil : branche src/routes/+page.server.ts sur listHomeLeaves, listOaths (publics) et getPublicSettings ; si la base ne répond pas, leaves = null (la page affiche déjà la phrase prévue). Dans src/routes/+layout.svelte, applique data.theme sur <html> côté client à chaque navigation (le hook serveur le pose au premier rendu).
Captures exigées : /entrer, /entrer/inscription (deux étapes), /compte et /compte/collection (--compte=alice, thème nuit et Papier), /plus (--compte=alice, 390), une 404.
